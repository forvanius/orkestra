# Why the rules are what they are

Measured runs behind orkestra's rules. Full numbers: `docs/measurements.md` in this plugin.

- The biggest cost is the conductor's context: in one large run the conductor was 57% of all reads, each call re-reading ~300 K tokens.
- Code, images and review on Codex, mechanical runs on a small model → ~15× cheaper **in Claude tokens** than the same scale done by Claude agents; Codex's own tokens were not counted. Codex reviews found real bugs in most rounds (9 of 13; 3 of 4).
- The Codex sandbox may be unable to run Python, a browser, a game engine or your smoke tests → the verifier runs tests. Tests written without a browser often fail on first real run; never trust a PASS that skipped the smoke run.
- The conductor never opens images (capture → send to the user). ≤3 parallel smoke runs **started at low priority** (`guarded.js heavy`; give the verifier the command in its brief — the machine is the user's), ~25 min time limit in every worker brief.
- **Written rules get skipped in long sessions.** First real audit (41 h, 3 chained sessions, 39 commits): model routing was right on every call, but the conductor took 96% of reads (context up to 674 K), 19 Codex writes merged with **0 reviews**, no board, 66 images and 44 log polls by the conductor, 84% of Codex calls on `high`. Hence the hard gates below: board required, a gate before every merge, a handoff limit.
- **Second real run (after the gates, 3.5 h):** conductor 78% (was 96%), 4 gated reviews that stopped 2 real bugs (a wrong fix and a seam jump), board + `board_check` used, 0 images opened, all Codex on `medium`. Still skipped: handoff (47 calls over 200 K → now a hook) and low priority for smoke runs (13/13 at normal priority, machine at 85% CPU).
- **Third audit (46 sessions, 2026-11):** a +150 K limit stopped sessions after about 80–135 conductor calls, often after 1–2 user requests. Each call costs at least ~350 tokens and 1.1–1.9 K on average, so the number of calls drives growth more than their content; 55% of the conductor's shell calls were still reads. Routing had collapsed: 673 Codex calls against 235 Claude worker/verifier runs, one Codex model for everything. Hence the higher limit, `close_part.js`, the routing table and the other-vendor reviewer.
- **Unmeasured additions:** lane matrix, board file, double review (adapted from ECC), the `spec` field + design note (adapted from superpowers), the routing table, `orkestra:reviewer`, plan consultation, section leads and the logistics scripts. Measure their effect in your next runs before adding more rules — above all whether Sonnet reviews catch as many real bugs as Codex reviews did, and how often an advisor's point changed the plan.
- **0.6.3:** Two real jobs exposed idle conductor wakes, long fix loops, mid-run hand-backs and refused report writes. Review names drifted from board parts, no-code closes and write surfaces needed explicit handling, and Claude quota lacked an estimate. The release moves routine writing to Codex, gates repeat reviews and measures spending against a board budget.
